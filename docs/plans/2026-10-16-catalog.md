# svelte-zukan カタログ本体 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `.zukan.svelte` と `Document.md` をコンポーネントの隣に置くだけで、一覧・iframe プレビュー・コード表示がそろうカタログを作る。

**Architecture:** Vite プラグインが `.zukan.svelte` を `svelte/compiler` の `parse` で解析し、セクション一覧とコードと Document.md の HTML を `<script module>` の `export const __zukan` として注入する。`Zukan` コンポーネントは利用側の `[...path]` ルートに置かれ、`page.params.path` から一覧・詳細・プレビューを出し分ける。プレビューは同じルートを iframe で開き、`Section` がコンテキストの section 名と title を比べて表示を切り替える。`zukanEntries` が prerender の `entries` を返し、全ページを静的に書き出せる。

**Tech Stack:** Svelte 5.57 (runes), SvelteKit 3.0, Vite 8, vitest 4（server / client の 2 プロジェクト）, marked, magic-string, adapter-static, vite-plugin-inspect 12 + @vitejs/devtools

**Spec:** `docs/specs/2026-10-16-catalog.md`

## Global Constraints

- コードを取り出す処理は正規表現ではなく `svelte/compiler` の `parse(source, { modern: true })` を使う
- スタイルは scoped CSS と `--zukan-*` カスタムプロパティのみ。Tailwind などに依存しない
- `import.meta.glob` はライブラリ側に書かない
- デコレーターや CLI は作らない
- 依存を足したら `pnpm install` はユーザーに手元で実行してもらう（サンドボックスではストアロックに書けない）。npx は `npm_config_cache=$TMPDIR/npm-cache` を付ける
- コミットメッセージは `feat: ...` / `chore: ...` の日本語。経緯や Co-Authored-By は書かない
- 各タスクの終わりに `pnpm lint` と `pnpm check` が通ること
- client プロジェクトのテストは Chromium を使う。`~/Library/Caches/ms-playwright` に既に入っているが、バージョン違いで起動しなければ `pnpm exec playwright install chromium` をユーザーに手元で実行してもらう
- リポジトリ内でも `import { Section } from 'svelte-zukan'` と書き、Vite の `resolve.alias` と tsconfig の `paths` で `./src/lib/index.ts` に向ける（Task 2 で設定。Kit 3 は `alias` オプションを非推奨にし、subpath imports は `#` 始まりしか使えないため）

## Review Focus

- `title` に `"` や日本語や空白を含むセクション → URL は `encodeURIComponent`、注入する JS は `JSON.stringify` で壊れない（Task 1, 6 のテスト）
- `<script lang="ts">` を持ち、`<script module>` も既に持つファイル → 既存の module script に追記され、コンパイルが通る（Task 1 のテスト）
- `paths.base` を設定したアプリや `/zukan` 以外のマウント位置 → `resolveBase` がリンクを正しく作る（Task 3 のテスト）
- セクションの中身のインデントがタブとスペース混在 → 共通の先頭空白だけを削り、内容を変えない（Task 1 のテスト）
- セクションがひとつもない `.zukan.svelte` → 詳細ページは Document.md だけを出し、エラーにしない（Task 1 のテスト）

- `keeps lang only when the source script has it`: `<script>` のときは `<script>` で出す

- `dedents mixed indentation by common prefix`: `\t\t<A />\n\n\t\t\t<B />` → `<A />\n\n\t<B />`（空行は共通プレフィックスの計算に入れない）
- `returns [] when no sections`
- `throws on dynamic title`（`title={x}`）、`throws on duplicate title`、`throws on nested Section`（`{#if}` の中の `Section` も含む）。エラーメッセージに `filename` と行番号を含む
- 以下の `out` は `transformZukan(...).code`
- `transformZukan appends to existing module script and compiles`: `<script module lang="ts">export const x = 1;</script>` と `<script lang="ts">` を持つソースを `transformZukan` に通し、`svelte/compiler` の `compile(out, { filename, generate: 'client' })` が例外を投げず、`out` に `export const __zukan =` が 1 回だけ出る。`out.split('\n').length` が `source.split('\n').length` と等しい（行がずれない）
- `transformZukan inserts at module content start`: module script の中身が改行なしの `// comment` で終わるソースでも、`compile` した結果のモジュールに `__zukan` が export されている（`compile(...).js.code` に `__zukan` が含まれる）
- `transformZukan returns a source map`: `map.sources` が `[filename]`、`map.sourcesContent[0]` が元のソース、`map.mappings` が空でない
- `transformZukan adds module script when missing`: `out.startsWith(source)` が真（末尾に足すので元の行が動かない）。出力の `__zukan` 部分を `JSON.parse` で戻すと `{ sections: [{ title: 'a "b" 日本語', code: ... }], doc: '<p>x</p>' }` と一致する

- [ ] **Step 3: `extract.ts` を実装する**

- `parse(source, { modern: true })` の `ast.fragment.nodes` のうち `type === 'Component' && name === 'Section'` をセクションとする。`fragment.nodes` 以下を再帰的にたどり、トップレベル以外で `Section` を見つけたらエラー
- `title` は `attributes` の中の `name === 'title'` で、`value` が `Text` 1 つの配列であること。それ以外はエラー
- 本文は `source.slice(fragment.nodes[0].start, fragment.nodes.at(-1).end)` を前後の空行を除いて dedent する。共通の先頭空白は空行を除いた行から求める
- 識別子の収集は AST を汎用的に再帰する。`metadata` と `parent` のキーは飛ばす（循環参照や余計な Identifier を拾わないため）。拾うのは（`type === 'Identifier'` の `name`、`Component` / `UseDirective` / `TransitionDirective` / `AnimateDirective` の `name.split('.')[0]`）。余分に拾っても、トップレベル定義と照合するだけなので害はない
- 定義の対象は `ast.instance.content.body` の `ImportDeclaration`（source が `svelte-zukan` のものを除く）、`VariableDeclaration`、`FunctionDeclaration`、`ClassDeclaration`。各文の宣言名と、文の中で使っている識別子を求め、参照名の集合が増えなくなるまで繰り返す
- 定義は `source.slice(node.start, node.end)` を 2 スペースでインデントして並べる
- 行番号はエラー時に `locate` 相当の計算（`source.slice(0, start).split('\n').length`）で出す
- `transformZukan` は `ast.module` があれば `ast.module.content.start` の位置に `export const __zukan = ${JSON.stringify(meta)};` を改行なしで挿入し、なければ末尾に `\n<script module>export const __zukan = …;</script>\n` を足す。挿入は `new MagicString(source).appendLeft(pos, text)` で行い、`generateMap({ hires: 'boundary', source: filename, includeContent: true })` を `map` として返す
