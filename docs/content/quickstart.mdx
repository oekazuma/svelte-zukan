svelte-zukan works with plain Vite + Svelte and with SvelteKit 3 or later. It needs Vite 8 or later, Svelte 5.20 or later, and Node 22.17 or later. It uses Vite-specific hooks (`configureServer`, `hotUpdate`, `buildApp`), so it does not work with other bundlers.

## Install

<CodeGroup>

```sh npm
npm install -D svelte-zukan
```

```sh pnpm
pnpm add -D svelte-zukan
```

```sh Yarn
yarn add -D svelte-zukan
```

</CodeGroup>

## Add the plugin

Place `zukan()` before `sveltekit()` or `svelte()`.

<CodeGroup>

```ts SvelteKit
// vite.config.ts
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';
import { zukan } from 'svelte-zukan/vite';

export default defineConfig({ plugins: [zukan(), sveltekit()] });
```

```ts Vite + Svelte
// vite.config.ts
import { svelte } from '@sveltejs/vite-plugin-svelte';
import { defineConfig } from 'vite';
import { zukan } from 'svelte-zukan/vite';

export default defineConfig({ plugins: [zukan(), svelte()] });
```

</CodeGroup>

## Write a catalog file

Put `<Name>.zukan.svelte` next to the component, and wrap each example in `<Section>`.

```svelte
<!-- src/lib/Button/Button.zukan.svelte -->
<script lang="ts">
  import { Section } from 'svelte-zukan';
  import Button from './Button.svelte';
</script>

<Section title="Basic">
  <Button>Click me</Button>
</Section>

<Section title="Disabled">
  <Button disabled>Disabled</Button>
</Section>
```

## Open the catalog

Start the dev server and open `/__zukan/`. The catalog URL is also listed in the URLs printed to the terminal at startup.

If you set Vite's `base` or SvelteKit's `paths.base`, the catalog moves to `<base>__zukan/` (for example, `/app/__zukan/` when `base: '/app/'`).

In the catalog:

- Type in the search box, or press <kbd>/</kbd> to jump to it, to filter the components by ID and by section title. <kbd>J</kbd> and <kbd>K</kbd> move to the next and previous component, <kbd>T</kbd> switches between light and dark, <kbd>F</kbd> expands the preview in view, the arrow keys move through the component list (<kbd>←</kbd> and <kbd>→</kbd> close and open folders), and <kbd>?</kbd> lists the shortcuts
- A detail page with several sections has a table of contents beside it when the window is wide enough, and links to the previous and next components at the bottom
- Each section has width presets for a phone (375px), a tablet (768px), a laptop (1024px), a desktop (1280px) and the full width (or drag the right edge, or type a width in pixels), a button that switches the background between the theme's color, a checkerboard and a grid, a button that outlines every element of the preview, a button that checks the preview's accessibility with [axe-core](https://github.com/dequelabs/axe-core) (it lists what it finds, outlines the reported elements, checks again after each edit, and can simulate blurred vision and color vision deficiencies), a button that expands it over the page (<kbd>Esc</kbd> leaves), a link that opens the preview alone in a new tab, and a button that copies a link to the section at its current width and theme. A width narrower than the page is centered on a dotted background, so the device's edges stay visible on a wide screen; a wider one (such as the desktop preset on a laptop) is laid out at its real width and scaled down to fit, with the scale shown next to the width. The widths are remembered in this browser across reloads; a copied link opens with its own width and theme, without changing the theme you chose
- The theme button at the top of the sidebar switches the catalog and every preview between light and dark. It starts from your system's setting, and your choice is remembered in this browser. On a narrow screen, the component list folds under the menu button
