# svelte-zukan カタログ本体 設計

## 目的

SvelteKit アプリのコンポーネントの隣に `zukan/Foo.zukan.svelte` と `zukan/Document.md` を置くと、一覧・セクションごとのプレビュー・コード表示がそろう。利用側が書くのはルート 3 ファイルと Vite プラグインの登録だけにする。prerender で全ページを静的に書き出せるようにする（adapter-static 対応）。

## 利用側のセットアップ

```ts
// vite.config.ts
import { zukan } from 'svelte-zukan/vite';
export default defineConfig({ plugins: [zukan(), sveltekit()] }); // zukan() は sveltekit() より前
```

```ts
// src/routes/zukan/groups.ts
import type { Groups } from 'svelte-zukan';

export const groups: Groups = {
  components: import.meta.glob('/src/lib/**/zukan/*.zukan.svelte'),
  pages: import.meta.glob('/src/routes/**/zukan/*.zukan.svelte')
};
```

```ts
// src/routes/zukan/[...path]/+page.ts
import { zukanEntries } from 'svelte-zukan';
import { groups } from '../groups';

export const prerender = true;
export const entries = () => zukanEntries(groups);
```

```svelte
<!-- src/routes/zukan/[...path]/+page.svelte -->
<script lang="ts">
  import { Zukan } from 'svelte-zukan';
  import { groups } from '../groups';
</script>

<Zukan {groups} />
```

- glob は `groups.ts` に 1 回だけ書き、`+page.ts`（`entries` 用）と `+page.svelte`（表示用）の両方から import する。`+page.svelte` が直接 import すれば足りるので、`+layout.ts` の `load` で渡す形はやめる
- 静的に書き出さないなら `+page.ts` は不要

rest パラメータ名は `path` 固定にする（`Zukan` が `page.params.path` を読むため）。README に明記する。

Provider が必要なら `src/routes/zukan/+layout.svelte` で囲む。ルートの `+layout.svelte` にアプリのヘッダーなどがあるとプレビューにも出るので、その場合は `(zukan)` のようなルートグループに分けるか `+page@.svelte` でレイアウトを外す。README にこの注意を書く。

## カタログファイルの書き方

```svelte
<!-- src/lib/Button/zukan/Button.zukan.svelte -->
<script lang="ts">
  import { Section } from 'svelte-zukan';
  import Button from '../Button.svelte';

  let count = $state(0);
  const label = $derived(`${count} 回押した`);
</script>

<Section title="基本">
  <Button onclick={() => count++}>{label}</Button>
</Section>

<Section title="無効">
  <Button disabled>押せない</Button>
</Section>
```

- `<Section>` はトップレベル（他の要素やブロックの中ではない位置）に置く。`title` は静的な文字列のみ。動的な値、重複、ネストはプラグインがビルドエラーにする（ファイル名と行を出す）
- `Document.md` は任意。あればページ上部に HTML として表示する

## URL

カタログのマウント位置を `<base>` とする（上の例では `/zukan`）。

| URL                                             | 表示                                      |
| ----------------------------------------------- | ----------------------------------------- |
| `<base>`                                        | 一覧                                      |
| `<base>/<group>/<Name>`                         | 詳細ページ                                |
| `<base>/preview/<group>/<Name>?section=<title>` | iframe 用プレビュー（カタログの UI なし） |

- `<Name>` はファイル名から `.zukan.svelte` を除いたもの
- `<base>` は `page.url.pathname` の末尾から `page.params.path` を取り除いて求める。props で渡す必要はなく、`paths.base` を設定したアプリでも動く
- グループ名 `preview` は予約語としてエラーにする。同じグループ内で `<Name>` が重複したらエラーにする（エラーメッセージに両方のファイルパスを出す）

## 静的書き出し

- `zukanEntries(groups)` は `[{ path: '' }, { path: '<group>/<Name>' }, …, { path: 'preview/<group>/<Name>' }, …]` を返す。glob のキーだけから作るので、モジュールは読み込まない（同期関数）
- 詳細ページの中身とプレビューの iframe は `{#await}` の中にあり SSR の HTML に出ないので、prerender のクロールでは見つからない。そのため `entries` で全ページを明示する
- プレビューのセクション指定は `?section=<title>` のまま、クライアントでだけ読む。理由:
  - プレビューの中身は `{#await}` の中にあり、もともと SSR の HTML に出ない。セクションをパスに入れても、書き出した HTML の中身は変わらない
  - パスに入れると、`entries` を作るためにビルド時に全モジュールを読み込んでセクション名を集める必要がある。クエリなら glob のキーだけで足りる
  - 書き出すページ数がセクション数ではなくコンポーネント数で済み、`/` などを含む title のエンコードも気にしなくてよい
- 読み方: `browser`（`$app/environment`）が真のときだけ `page.url.searchParams.get('section')` を読む。prerender 中に `searchParams` に触れると SvelteKit がエラーにするため。`section` がないときは全セクションを表示する（プレビューの URL を直接開いたとき用）

## 一覧と詳細

- サイドバー: グループの並び順は `groups` のキー順、グループ内は名前の昇順。各項目にグループ名のバッジを付ける
- 一覧ページ（`<base>`）: サイドバーと同じリストを本文にも出す
- 詳細ページ: コンポーネント名とバッジ、`Document.md` の HTML、セクションごとに「見出し、プレビュー、コード」を縦に並べる
- 存在しないパスは「見つかりません」を表示する
- プラグイン未登録でメタデータがないモジュールは「Vite プラグイン `zukan()` が登録されていません」と表示する

## プレビュー

- セクションごとに `<iframe src="<base>/preview/<group>/<Name>?section=<title>">`
- プレビュー側は `.zukan.svelte` 全体を描画し、`Section` がコンテキストの `section` と自分の `title` を比べて、一致したものだけ `children` を描画する。コンテキストがない場所（カタログ外で直接描画した場合や、`section` 指定のないプレビュー）では常に描画する
- 高さは中身に合わせる。同一オリジンなので親が `iframe.contentDocument` 内のラッパー要素を `ResizeObserver` で監視する
- 幅はセクションごとに持つ。プリセットボタン（375 / 768 / 1024 / 1280px と「100%」）と、フレーム右端のハンドルのドラッグで変える。現在の幅を px で表示する。ドラッグ中は iframe に `pointer-events: none` を付ける
- 既定は 100%

## コード表示

- セクションの中身（`<Section>` の開始タグと終了タグの間）を取り出してインデントをそろえる
- テンプレート内で参照している識別子のうち、インスタンススクリプトのトップレベルで定義されているもの（`import`、`let`/`const`/`var`、`function`、`class`）の定義を `<script>` ブロックとして先頭に添える。定義がさらに参照している定義も含める（例の `label` が `count` を参照している場合は両方出す）。元の並び順を保つ。`svelte-zukan` からの import は除く
- 元ファイルの `<script lang="ts">` の `lang` を引き継ぐ
- `<details>` で折りたたみ、既定は閉じる。コピーボタンを付ける（`navigator.clipboard.writeText`）
- シンタックスハイライトはしない

## Vite プラグイン `zukan()`

[Vite の Plugin API](https://vite.dev/guide/api-plugin) に沿って作る。

- 名前: `name: 'vite-plugin-svelte-zukan'`。警告やエラーに出る名前なので、Vite の命名規則（フレームワーク固有のプラグインは `vite-plugin-<framework>-` を前に付ける）に合わせて、どのプラグインか分かるようにする
- `enforce: 'pre'`。vite-plugin-svelte のコンパイルより前に変換する。README で `zukan()` を `sveltekit()` より前に置くよう案内する
- `transform` はフックフィルターを使う

```ts
const ZUKAN_ID = /^[^?#]+\.zukan\.svelte(?:[?#]|$)/;
const SVELTE_STYLE_ID = /[?&]svelte&type=style/;

transform: {
  filter: { id: { include: ZUKAN_ID, exclude: [/^\0/, SVELTE_STYLE_ID] } },
  handler(code, id) {
    if (!isZukanId(id)) return; // フィルター非対応の古い Vite / Rollup 向けに同じ判定をする
    ...
  }
}
```

- フィルターは vite-plugin-svelte と同じ形にする。`?` 付きの id も対象にし、vite-plugin-svelte が CSS 用に作る仮想モジュール（`Foo.zukan.svelte?svelte&type=style&lang.css`）と `\0` 付きの仮想モジュールは除く。`$` で終わる正規表現だと、クエリの付いた id を取りこぼす
- 解析は `svelte/compiler` の `parse(source, { modern: true })` で行い、次の export を足す
  - `<script module>` があるときは、その中身の先頭（開始タグの `>` の直後）に改行を入れずに 1 行で足す。中身の末尾が改行なしの `// コメント` で終わっていても、挿入したコードがコメントにならない
  - ないときは、ファイルの末尾に `<script module>` ごと足す
- 挿入は `magic-string` で行い、`generateMap({ hires: 'boundary', source: id, includeContent: true })` の map を返す。挿入位置より前の行は動かないので、map を使わないツールでもエラーの行番号はずれない

```ts
export const __zukan = {
  sections: [{ title: '基本', code: '<script lang="ts">\n...' }],
  doc: '<h1>...</h1>' // Document.md がなければ null
};
```

- `Document.md` は `marked` で HTML にする。`this.addWatchFile` で依存として登録する（Vite 8 は transform 中に `addWatchFile` したファイルをモジュールグラフ上の import として扱う）
- 変換は環境（client / ssr）ごとに呼ばれる。結果はソースと Document.md だけで決まり、`this.environment` や `ssr` で分岐しないので、どちらの環境でも同じになる
- HMR: `hotUpdate` フック（Vite 6 以降の環境ごとのフック）で扱う
  - 対象は `.zukan.svelte` の変更と、`zukan/Document.md` の作成・変更・削除
  - 各環境で、該当する `.zukan.svelte` のモジュール（Document.md の場合は同じディレクトリの `*.zukan.svelte`）を `this.environment.moduleGraph.invalidateModule` で無効化する
  - client 環境では `this.environment.hot.send({ type: 'full-reload' })` を送り、`[]` を返す
  - 部分的な HMR にしない理由: `__zukan` はコンポーネントの外の export なので、Svelte の HMR はコンポーネントだけを差し替える。`Zukan` が読み込み済みの `__zukan`（セクション一覧、コード、Document.md）は古いまま残る。コンポーネント本体（`Button.svelte` など）の変更はこのフックの対象外で、通常の HMR になる
- 解析部分（文字列を受け取り sections を返す関数）はファイルシステムに触れない純粋関数にして、単体テストする
- Vite 専用のフック（`hotUpdate`）を使うので Rolldown 単体のプラグインにはしない。README にその旨を書く

## 見た目

- すべて scoped CSS。利用側の Tailwind などには依存しない
- テーマ用の公開カスタムプロパティ（利用側が `:root` などで上書きする）

| 変数                    | 既定値                    |
| ----------------------- | ------------------------- |
| `--zukan-color-bg`      | `#fff`                    |
| `--zukan-color-text`    | `#1f2328`                 |
| `--zukan-color-muted`   | `#59636e`                 |
| `--zukan-color-border`  | `#d1d9e0`                 |
| `--zukan-color-accent`  | `#0969da`                 |
| `--zukan-color-code-bg` | `#f6f8fa`                 |
| `--zukan-font-family`   | `system-ui, sans-serif`   |
| `--zukan-font-mono`     | `ui-monospace, monospace` |
| `--zukan-sidebar-width` | `240px`                   |

- ルート要素で `--_bg: var(--zukan-color-bg, #fff)` のように内部変数へ受け、子はそれを使う（ルート要素で公開変数を定義すると `:root` での上書きが効かなくなるため）
- ダークモードの既定値は持たない。必要なら利用側が上の変数を上書きする

## パッケージ

- `svelte-zukan`: `Zukan`、`Section`、`zukanEntries`、型 `Groups`
- `svelte-zukan/vite`: `zukan`
- `peerDependencies` に `@sveltejs/kit`（`$app/state` を使うため）を足す。`dependencies` に `marked` と `magic-string` を足す
- `keywords` に `vite-plugin` を足す
- 開発用に `vite-plugin-inspect`（v12）と `@vitejs/devtools`（0.7 以上）を devDependencies だけに入れる。このリポジトリの `vite.config.ts` で `devtools: true` と `Inspect()` を設定し、`.zukan.svelte` の変換結果を確認できるようにする。配布物には含めない
- `files` で `dist/**/zukan/**` を除く（ドッグフーディング用のカタログファイルを配布物に入れない）

## ドッグフーディング（`src/routes`）

- `/zukan` にこのライブラリ自身のカタログを置く。`/` からリンクする
- adapter-auto から adapter-static に切り替え、`src/routes/+layout.ts` に `export const prerender = true` を置く。`pnpm build` の出力（`build/`）に一覧・詳細・プレビューの HTML が入ることを確認する。GitHub Pages へのデプロイは今回入れない
- リポジトリ内のカタログファイルも利用側と同じく `import { Section } from 'svelte-zukan'` と書く。`vite.config.ts` の `resolve.alias`（`/^svelte-zukan$/` を `./src/lib/index.ts` に向ける。完全一致にして `svelte-zukan/vite` を巻き込まない）と `tsconfig.json` の `paths` で解決する。Kit 3 は `alias` オプションを非推奨にし、代わりの subpath imports は `#` で始まる名前しか使えず、利用側と同じ書き方にできないため
- グループは 2 つにして、表示順とバッジを確認できるようにする
  - `ui`: ライブラリ内部の UI 部品（`CodeBlock` など）の `zukan` ファイル
  - `examples`: `src/examples/` に置くサンプル（`Button` など）

## やらないこと

- デコレーター、単体の CLI、シンタックスハイライト、検索、ダークモードの既定値
- サイドバーの階層表示（`<Name>` はファイル名だけで決める。同名はエラーにする）
- `import { Section as S }` のような別名（`Section` という名前のコンポーネントだけをセクションとして扱う）
- トップレベルの `{#snippet}` をセクションから参照したときの定義の添付
- 詳細ページとプレビューの中身を SSR の HTML に入れること。`.zukan.svelte` は `{#await}` で読み込むので、書き出した HTML には外枠（サイドバー、見出し）だけが入り、中身はハイドレーション後に出る。カタログは JS が動く前提で使うものなので許容する
- 未知のパスで 404 を返すこと（「見つかりません」を 200 で表示する。`entries` で書き出すページには出ない）
