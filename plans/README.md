## Findings considered and rejected

- `$app/env` in the SvelteKit runtime guide looked like a typo for `$app/environment`. It is correct: SvelteKit 3.1.0's types declare `$app/env`.
- npm/yarn workspaces not being discovered was reported as a bug. It is documented behaviour; it became the optional direction plan 014 instead.
- Splitting the release job further (install only the published package, gate publishing behind an environment): changes release mechanics that changesets/action expects, and the existing mitigations (SHA pins, `allowBuilds`, `minimumReleaseAge`, trusted publishing) are already real.
- `components/` importing from `app/` (`hash.ts`, `i18n.ts`): a layering smell with no cost today.
- `pnpm run package` running in both the `check` and `test` CI jobs: about 30 s, in parallel jobs; an artifact hand-off costs more than it saves.
- A pre-commit formatting hook: adds a dependency for something `pnpm run lint` already catches (AGENTS.md: no new dependencies for small things).
- `EntryList` regrouping entries with array copies (O(n²) per group): not measurable at realistic catalog sizes.
- The Playwright cache key read with `grep` and its `restore-keys`: works today; the risk is hypothetical.
- Changesets possibly versioning the private `example` package: likely a no-op (it only has `svelte-zukan` as a devDependency); check the next Version Packages PR instead of planning.
- Investigate-only, not planned: auto-height iframes growing with `100vh` content; app-level build options leaking into the catalog environment; symlinked or junctioned roots compared inconsistently; `src/` created after the dev server starts; the base-prefixed URL passed to `transformIndexHtml`; a repository living under a directory named `node_modules`; options validation for `title`, empty `groups` and nested group dirs; the generated entry having no `.catch` in the static build; a separate `Marked` instance instead of the global one; declaring `@sveltejs/kit` / `@sveltejs/vite-plugin-svelte` as optional peers; running CI on the minimum Node version (22.17); focus management and a skip link after navigation (needs new UI strings).
- Second audit, considered and not planned:
  - One locale type shared by plugin and UI (`'en' | 'ja'` written in 5 files): two locales are closed by design; a third is out of scope.
  - Folding the small duplicates in `index.ts` (two `/__zukan` redirects, two `renderHtml` call sites): about 15 lines, no cost today.
  - The `takumi-js` override in `pnpm-workspace.yaml`: still needed with blume 2.2.4, which still reads the old `ranges` field. Keep it.
  - The `svelte` peer floor (`^5.20.0`) is lower than what Vite 8 setups can install (vite-plugin-svelte 7 needs `^5.46.4`): harmless, informational only.
  - "1.0 MB, 4 packages" in `docs/content/why.md` could not be re-measured offline; plan 029 Step 1 measures it.
  - A hierarchical sidebar, and a `catalog.json` manifest for outside tooling: no demand yet; the second conflicts with the "not a test runner" positioning in why.md.
  - A docs recipe for publishing the catalog at `/__zukan/` next to the deployed app: offered as a direction option and not selected. A plugin option for it was rejected outright (adapter output dirs cannot be read from the plugin).
  - Investigate only: search not matching NFD file names on macOS; the auto-height `ResizeObserver` created in the parent window (Firefox/Safari untested); a `?` or `#` in a catalog directory name breaking the component import; absolutely positioned preview content (dropdowns) being clipped.
